- 迭代：B1.5 / T-030；测试日期：2026-11-09。
- 代码基线：80c8dd9，加本轮未提交的采集配置与归档占位装配修复。

- 判定范围：文件 → Fluent Bit → Kafka → Logstash/Elasticsearch，以及 Kafka → log-service → foodmap_log_db。

## 2. 联调目标与联调安全点

准入检查：最新认证接口可被 curl/验证脚本调用；日志组件已启动；流水号可追踪；前端可发起真实请求的 UI 能力不属于本次日志验收范围，另以全套回归结果说明。

等级为 L3 环境联调。已有后端接口可调用、requestId/traceId 可追踪、日志库独立、必要容器运行，允许开始日志环境验证。前端职责：本切片使用脚本发起请求，不作 UI 验收；原有 UI 场景单独回归并如实记录失败。

不验收 OSS 冷归档、生产权限/TLS、日志平台全部能力、六类推荐可见范围或 PUBLIC 统计。

## 3. 后端职责与契约

- 最新认证实例：127.0.0.1:18081，local，Nacos 注册关闭，日志目录 /tmp/foodmap-orbstack-logs。
- 最新日志服务：127.0.0.1:18089，Kafka 消费显式开启，其他清理/归档调度保持关闭。
- 原有用户服务 8082 支持注册开通，现有网关/认证/用户实例保留。
- 接口：GET /internal/auth/health 返回 200；POST /api/auth/login 对不存在账号返回 401，合法账号返回 200；注册与注销返回 200。
- 响应与日志透传 X-Request-Id/X-Trace-Id，不保存密码或 Token；凭据仅驻留验证进程内存。
- Kafka 五类 topic 的分区数 3、副本数 1；日志数据库为 foodmap_log_db，不访问其他业务服务的表。

## 4. 环境和测试数据

OrbStack aarch64，Docker 27.5.1，约 8GB 内存；Apache Kafka 3.9.1、Fluent Bit 3.1、Elasticsearch/Logstash 8.15.3。数据迁移执行 V1/V2。初始化容器正常退出 0 是成功状态。

测试账号由时间戳和随机后缀生成；Refresh 会话注销，测试账号和日志保留用于追溯。原数据库卷不删除。Compose 启动迁移时重建过 PostgreSQL 容器，保留原卷；随后原认证/用户健康检查 200。

## 5. 验收场景与验证方式

运行 harness/scenarios/b1-logging-closure.yml 调用相邻 Python 探针：

1. 健康请求 200；不存在账号登录 401。
2. 注册、成功登录、注销均 200。
3. 每个请求在 JSON 文件、ES 和日志数据库均存在，流水号、服务名、事件名一致。
4. 数据库记录真实 HTTP 方法、路径、状态码、耗时和 Kafka 消费位点。
5. ES 不含时间解析失败标签；业务时间和采集时间分离。
6. 文件和 ES 不含本轮密码、Access Token、Refresh Token。
