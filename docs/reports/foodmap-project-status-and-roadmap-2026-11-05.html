真实业务前注册事务与跨服务一致性

3.2 代码实现必须遵守的边界

01 / 数据所有权

一个服务拥有自己的数据库

跨服务只通过 API 或事件；引用业务主键，不引用自增 id。Flyway 管理迁移；Entity、DTO、VO 分离；标准 Mapper 和复杂 DefineMapper 分工。表字段中文注释与实体 Javadoc 保持一致。

02 / 权限与隐私

后端决定谁能看见什么

写操作从可信 Token 取 userId；列表、详情、评论、统计和图片采用一致授权口径。不能只过滤正文而泄露菜名、作者或私密计数。客户端 scope 只是查询意图。

03 / 事务与事件

短事务，可靠补偿，幂等消费

多表写在服务层设置本地事务；跨服务写用补偿／Outbox 与幂等。数据库连接中不等待远程接口或锁；先拿锁再开短事务。锁只能通过统一接口，有 owner、租约与续期上限。

04 / PUBLIC 口径

公开索引必须支持撤回

仅 PUBLIC 且 NORMAL 内容参与全站统计。转私密、隐藏、删除、关系变化均需判断影响；幂等键、事件版本、重放和对账不可省略。群组私有统计单独处理。

05 / 媒体与离线

图片和缓存继承内容边界

图片 URL 不能绕过所属推荐权限；验证媒体归属、类型、大小与引用状态。离线只读低风险摘要，不缓存社交推荐详情／评论正文。离线包文件与业务缓存分开管理。

06 / 契约与可排障性

稳定错误码，安全日志

统一 success/status/code/message/data；401 与 403 分开。每条调用可由 requestId/traceId 追踪。禁止记录 Token、密码、密钥、完整联系方式与私密正文；SQL 必须脱敏。

07 / 地理数据

先定义坐标与范围语义

高德坐标、后端存储与客户端绘制应明确转换边界，不能只填 SRID 而忽略来源。校验经纬度／bbox、分页与缩放层级；用同一地标和边界点验证查询、距离与点位一致性。

08 / 生产部署

默认配置不能直接代表生产就绪

生产密钥必须外部化；内部组件不暴露裸公网，跨云先建立 VPN。固定镜像版本，落实备份恢复与资源预算。现有模板仍有 latest 标签及业务服务占位，部署前必须收口。

项目既定规则来源：E01 E02 E03 E05。地理一致性、性能门槛与扩展指标是建议补充的验收关注点。
