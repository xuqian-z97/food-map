# A-007 认证密钥与 Token 闭环

## 1 测试说明

范围：T-025（Token 密钥统一注入与 fail-fast）、T-026（Access/Refresh Token 严格分段）、T-027（登出必须写拒绝名单）。
环境：本地 PostgreSQL（`foodmap_auth_db` / `foodmap_user_db`）、Redis、Auth 8081、Gateway 8080，均为包含本次代码的新构建。
测试数据：场景自动生成的 `zxq_vk_<epoch>` 账号，teardown 按 `accountId` / `userId` 清理并断言归零。
已知限制：iOS UI 自动化在当前沙箱无法创建伪终端，本次只执行接口级与单元测试。

## 2 用例设计

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| C1 | 生产 profile 缺少 `FOODMAP_TOKEN_SECRET` | 启动失败，不回落默认密钥 |
| C2 | 密钥长度不足 32 字符 | 启动失败并提示检查环境变量 |
| C3 | 合法 Access Token（3 段） | 解析成功 |

| C6 | 篡改 payload / signature | 401 |
| C7 | 类型错配（Refresh 当 Access、Access 当 Refresh） | 401 |
| C8 | 带有效 Access Token 登出 | Redis denylist +1，旧 Access 立即 401，Refresh 401 |
| C9 | 带无效 Access Token 登出 | 401，denylist 不写入 |
| C10 | 不带 Authorization 登出 | 200，只撤销 Refresh；旧 Access 仍 200，denylist 不变 |
| C11 | 场景 teardown | 本轮 `auth_accounts`、会话、绑定、Token、登录日志计数归零 |

## 4 未覆盖项与风险

- 两个 iOS XCUITest 场景（`b1-ui-login`、`b1-register-validation`）因沙箱无法创建伪终端未执行；它们的后端断言与 F-024 无直接关系。
- Access Token 仍是自研 HMAC 结构，`parse()` 的段数规则与 `issueRefreshToken()` 的 nonce 追加强耦合，后续改 Token 结构必须同时改两处。
- 不带 Authorization 登出时旧 Access Token 在自然过期前仍可用，这是为兼容旧调用方保留的行为边界；客户端登出必须携带 Access Token。
- `HmacTokenIssuer` 的两个构造器都直接赋值 `tokenCodec`，Spring 只使用带 `TokenSecretProperties` 的构造器，测试使用字符串构造器。

## 5 结论

通过。密钥注入实现生产缺失即失败，Token 分段按类型严格校验，登出链路在带 Token 与不带 Token 两种语义下均符合预期，且追加后缀绕过已被接口级与单元测试双重覆盖。
