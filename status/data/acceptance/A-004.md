# A-004 当前用户与启动恢复

## 1 测试说明

范围：`GET /api/users/me` 建立会话、冷启动恢复、以及三类异常下本地认证状态的去留。
环境：本地 Gateway/Auth/User，iPhone 17 Pro 模拟器（iOS 26.5）Debug 构建。
测试数据：账号 `zxq_ios_152532`（userId 200024）；停用场景直接改库 `auth_accounts.account_status`，测完恢复 `NORMAL`；过期场景用本地 HMAC 密钥构造 `exp=2026-11-05T06:00:00Z` 的 Access Token，Token 只在内存传递，不写证据文件。
已知限制：未覆盖用户被删除、网关 504 超时、真实断网切换。

## 2 用例设计

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| C1 | 登录后 `GET /api/users/me` | 200，返回 userId 200024 |
| C2 | 冷启动恢复会话 | Token 有效时建立会话，`sessionNil=false` |
| C3 | 临时失败（网关不可用） | 不清 Token，恢复后会话可重建 |
| C4 | Access Token 过期 | 401「Access Token已过期」，清理本地 Token 并回登录页 |
| C5 | 账号被停用 | 403「账号状态不允许登录」，不落任何本地认证状态 |

## 3 执行结果

| 编号 | 结果 | 证据 |
| --- | --- | --- |
| C1 | 通过：`me` 200 | `evidence/2026-11-05-retest-logout.txt` 第 3 步 |
| C2 | 通过：`retention.afterRecovery userId=200024` | `evidence/2026-11-05-ios-error-states.txt` |
| C3 | 通过：`afterTempCall tokenPresent=true` / `afterRestoreDead tokenPresent=true` | 同上 |
| C4 | 通过：`expired.restore sessionNil=true tokenPresent=false message=Access Token已过期` | `evidence/2026-11-05-ios-disabled-and-expired.txt` |
| C5 | 通过：`disabled.login status=403 code=FORBIDDEN clearAuth=true tokenPresent=false` | 同上 |

运行记录：`runs/2026-11-05T15-49-it003-it012-error.json`、`runs/2026-11-05T16-01-it002-it004-session.json`。

## 4 未覆盖项与风险

- 停用账号依赖改库造数，后端尚无管理端停用接口，属测试夹具。
- 未覆盖用户被删除后 Token 仍有效、网关 504、真实断网重连。
- 过期 Token 只在启动恢复路径观察，未覆盖请求中途过期的自动刷新（属 F-022）。

## 5 结论

通过。当前用户查询、冷启动恢复在正常与异常路径都成立：临时失败保留 Token，过期或停用则清理并给出可读提示。
