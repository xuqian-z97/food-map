# A-008 内部信任与网关攻击面收敛（2026-11-10 复核重签）

## 1. 原结论纠正

原验收没有启动 admin，只手动构造 signer 测试 HTTP 客户端，遗漏真实装配缺陷：通用 signer 受 Feign 类存在条件限制，而 admin 并不依赖 Feign。本次将 signer 与 Feign 适配器分开装配，并以 admin 实际依赖的上下文及完整本地服务链路重新验证。原“admin 未执行仅属非阻塞”的判断不再作为本次依据。

## 2. 构建、环境与范围

- 基线 `f570464` 加本次工作树；精确输入 SHA-256 清单与聚合指纹见 evidence 的 build 字段。
- Gateway 8080、Auth 8081、User 8082、Admin 8088、Log 8089；后台实例启动成功，Flyway 校验现有 admin 库，无新增迁移。
- auth/admin 的 common classes 来自本次编译；user/log 保留 T-032 已运行的入站校验实例，本次未改变其主代码或配置。
- 新场景只读查询日志，nonce 为本轮随机值、Redis TTL 自动失效；不清理历史数据库记录。
- admin 请求使用现存 X-Admin 头骨架只是为了触发出站客户端，**不是管理员登录或权限安全验收**；T-033 仍不动。

新内部签名场景为 **1/1 verify 步骤**，其 Python 探针实际包含 **13 个 HTTP 检查**，不能混写成 13 个 verify 步骤。

单测：InternalService 相关 28（原 25 + 自动配置 3），admin 无 Feign 装配 1，原 HTTP 客户端断言 1；后端全量 **212/212，0 失败、0 跳过**。

严格套件：**11/11，0 失败、0 跳过**，含日志闭环与两个真实 XCUITest。日志验证专用 Auth 18081 已更新并显式指向 User 8082，解决此前旧实例调用 provision 被 401 拒绝的问题。
