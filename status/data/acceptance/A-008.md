# A-008 内部信任与网关攻击面收敛

## 1 测试说明

范围：T-031（关闭 gateway discovery locator）、T-032（内部接口服务身份签名）。
环境：本地 gateway 8080、auth 8081、user 8082、log 8089，Redis 与 PostgreSQL 使用本地容器；服务均使用 `d849f5a` 构建。
测试数据：`b1-logout` 场景自动生成的 `zxq_vk_<epoch>` 账号，teardown 按 `accountId` / `userId` 清理并断言归零。
已知限制：admin 服务未启动；日志服务使用临时端口实例。

## 4 未覆盖项与风险

- admin 服务未启动，管理后台到日志服务的完整 HTTP 链路未端到端执行，仅由单测覆盖签名头生成。
- 日志服务 8089 是临时实例，未进入 Compose；容器网络中服务名与端口的签名路径需要 T-035 一并验证。
- 健康检查豁免依赖 `/internal/{service}/health` 的路径约定，新增内部接口时不得复用该格式。
- nonce 去重依赖 Redis；Redis 故障时内部调用全部 401，这是有意 fail-closed，但会放大 Redis 故障影响面，需要监控。
- 内部签名密钥与 Token 密钥、pepper 是三个独立密钥，部署时必须分别注入，不能复用。

## 5 结论

通过。网关自动路由已关闭，内部接口在服务端强制校验调用方身份、时间窗、签名与 nonce 重放；未登记路径和越权服务返回 403，依赖不可用时 fail-closed。注册与登出主链路未回归。
