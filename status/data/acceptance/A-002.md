# A-002 刷新与退出登录

## 1 测试说明

范围：B1 认证切片的退出登录链路，包含服务端双 Token 失效与 iOS 端登出触发。
环境：本地 macOS + iPhone 17 Pro 模拟器（iOS 26.5），Gateway 8080 / Auth 8081 / User 8082，PostgreSQL + Redis + Nacos 以 Docker Compose 启动。
数据准备：每轮新建 `zxq_*` 测试账号，密码统一为测试密码，不记录明文；Token 只在内存中传递，不写入任何证据文件。
已知限制：未覆盖真实外网弱网、跨时区与多设备并发登出。

## 2 用例设计

| 编号 | 场景 | 步骤 | 期望 |
| --- | --- | --- | --- |
| C1 | 登出请求携带双 Token | iOS 登录后点击登出（自动化探针触发同一 `signOut` 路径） | `POST /api/auth/logout` 带 `Authorization` 与请求体 Refresh Token，返回 200 |
| C2 | 旧 Access Token 失效 | 用登出前的 Access Token 访问 `/api/users/me` | 401 `UNAUTHORIZED` |
| C3 | 旧 Refresh Token 失效 | 用登出前的 Refresh Token 调 `/api/auth/refresh` | 401 `UNAUTHORIZED` |
| C4 | 本地 Keychain 清理 | 登出后重启 App，再触发一次 `logout` 探针 | 探针记录 `hasSession=false`，不发起会话恢复 |
| C5 | 未认证与内部接口边界 | 无 Token 访问 `/api/users/me`；外部访问 `/internal/users/bootstrap` | 401；403 |

## 4 未覆盖项与风险

- 自动刷新（401 后自动续期）未实现，已拆为 F-022，不计入本验收单。
- 多设备同时登出、Refresh Token 并发刷新合并未覆盖。
- 真实网络切换、飞行模式恢复未覆盖。
- iOS 端验证依赖 Debug 构建中的 `LaunchAutomationProbe`（`#if DEBUG`），Release 包不含该探针。

## 5 结论

通过。B1 退出登录链路在接口级与 iOS 端均成立：登出后双 Token 失效，本地 Keychain 清理，重启保持未登录。BUG-011 可以关闭。
